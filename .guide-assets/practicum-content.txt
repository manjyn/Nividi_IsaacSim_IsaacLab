## 실습 환경과 합격 조건을 정한다
작업 대상은 평지에서 정지·전진·회전할 4족 로봇입니다. 장면 준비, 정책 훈련, 외부 프로그램 연결을 각각 독립적으로 시험하면 보행이 실패했을 때 원인 범위를 좁힐 수 있습니다.
### 예제를 사용하는 순서
1. Sim에서 큐브 낙하를 먼저 재현해 설치와 기본 물리를 확인합니다. URDF 가져오기는 공식 UR10 예제로 창 사용법을 익히고, 팀의 4족 모델이 있으면 이후 동일한 절차로 검사합니다.
2. Lab에서는 배포판에 등록된 ANYmal-D 평지 과제를 기준으로 삼습니다. 임의로 가져온 로봇 USD가 기존 과제의 관절 구성과 맞는지는 별도 검증이 필요합니다.
3. ROS 2 연결은 공식 바퀴 로봇 Nova Carter로 먼저 시험합니다. 여기서 확인하는 것은 통신·좌표·지도입니다. 4족 로봇에 연결할 때 속도 명령을 받을 보행 제어기를 따로 지정합니다.
### 준비물과 실행 위치
Windows 11 워크스테이션 예시입니다. 6.2 요구 사양표의 x86-64 최소 기준은 RAM 32 GB, RTX 4080·VRAM 16 GB, SSD 50 GB입니다. Lab의 학습 환경과 센서 수에 따라 메모리가 추가로 필요합니다. 공식 호환성 검사기로 GPU·드라이버를 확인하세요. Sim은 설치 폴더, Lab 명령은 v3.0.0 소스 폴더, ROS 명령은 ROS 환경이 적용된 터미널에서 실행합니다.
### 첫날 남길 결과
장면 USD와 참조 자산, 기록한 실행 명령, 관절 대응표, 시간대별 센서 로그, 정책 체크포인트를 같은 시험 번호로 묶습니다. 합격 조건의 예는 “정지→전진→정지 순서를 5회 반복하고 넘어짐과 속도 오차를 기록한다”입니다. 실제 허용 오차와 종료 조건은 로봇 사양에 맞춰 실행 전에 정합니다.

### 선택 → 경로 → 값 → 재생
Viewport(뷰포트)에서 큐브를 누르면 Stage(스테이지) 트리에서 해당 prim(프림)이 선택됩니다. Property(프로퍼티)에서 좌표나 물리 속성을 편집합니다. 아래 Content(콘텐츠)에서 찾은 파일은 프로젝트 자산이고, Stage에서 찾은 항목은 현재 장면에 배치된 대상입니다. Unity의 Scene·Hierarchy·Inspector·Project 창에 각각 대응시켜 보세요.

큐브의 Translate Z를 2로 설정하고 Play를 누릅니다. Stop 후 같은 큐브의 Property > Add > Physics > Rigid Body with Colliders Preset을 적용해 재생합니다. 앞에서는 떠 있고 뒤에서는 바닥에 멈추면 렌더와 물리 실험을 구별할 수 있습니다. File > Save As로 작업용 USD를 저장합니다.

영문 메뉴명은 그대로 찾기 위한 표기입니다. 아래는 Sim 6.2의 주요 경로이며, 제공 항목은 활성화한 Extension(익스텐션, 확장 기능)에 따라 달라집니다.

### 메뉴가 보이지 않을 때
Kit 기본 문서의 Window > Content는 Sim에서 Window > Browsers > Content에 해당합니다. Window > Layout > Save Layout 대신 Layouts > Save Layout을 찾으세요. 로봇 도구가 빠졌다면 Window > Extensions에서 확장 이름을 검색하고, 활성화한 뒤 Tools 하위 메뉴를 다시 확인합니다.
### 팀에 장면을 전달할 때
Save Layout은 창 배치를 저장합니다. 로봇·조명·관절 설정은 USD에 저장해야 합니다. 다른 PC로 전달할 때는 Collect and Save As의 결과를 별도 폴더에서 열어 메시와 텍스처 경로를 검사합니다. 참조를 유지한 작업본과 배포용 사본을 구분해 두세요.

## URDF를 가져오고 발 충돌체를 검사한다
!urdf-*gui_0.png|URDF Importer(임포터) · 중앙 파일을 선택한 뒤 오른쪽 USD Output, ROS Package List, Colliders 항목을 확인합니다. 공식 화면의 모델은 UR10입니다.|urdf
1. Window > Extensions에서 isaacsim.asset.importer.urdf를 확인합니다. File > Import에서 URDF를 고르고 USD Output에 쓰기 가능한 폴더를 지정하세요. package:// 메시 경로가 있다면 해당 ROS 패키지를 찾을 수 있게 등록합니다.
2. Import 후 몸통 크기를 실측과 대조합니다. 4족 로봇에서는 바닥에 고정되는 베이스 설정, 초기 발 높이, 관절 한계, 질량·관성을 확인하세요. 외형이 정상이어도 발 충돌체가 작거나 원점에서 밀리면 자세가 달라집니다.
3. 새 시험장에 변환된 USD를 참조합니다. 시각 메시와 충돌 형상을 번갈아 확인하고 평지에 세웁니다. 한 발만 바닥을 통과하면 발의 충돌체와 필터를, 모든 발이 통과하면 바닥과 물리 장면을 먼저 확인합니다.
### 인수 기록
한 행에 “링크 이름 / 메시 경로 / 발 충돌체 형상 / 좌표 오프셋 / 검사 결과”를 기록하세요. Merge Mesh(머지 메시)는 표시·충돌 구조를 다시 검토한 뒤 적용합니다. Unity에서 Renderer와 Collider를 따로 확인하는 습관이 여기에도 유효합니다.
@imp URDF 가져오기 절차 |urdf 옵션과 출력

## 한 관절의 방향과 응답부터 맞춘다
Articulation(아티큘레이션)은 관절로 연결된 링크를 함께 계산합니다. 무릎이 반대로 접히면 보상 함수를 바꾸기 전에 관절 축, 부모·자식 링크, 목표 부호부터 확인합니다.
### Gain Tuner에서 비교할 두 곡선
1. 시험용 복사본에서 몸통을 지지하고 발을 바닥과 떨어뜨립니다. Tools > Robotics > Asset Editors > Gain Tuner를 엽니다. Robot 목록에 없으면 Robot Schema 적용 상태와 gain_tuner 및 gain_tuner.ui 확장을 확인하세요.
2. Gain Settings에서 앞왼쪽 무릎을 고릅니다. 축·위치 제한·stiffness(스티프니스, 강성)·damping(댐핑, 감쇠)·출력 한계를 기록합니다. Test Gains에서 허용 범위 안의 작은 목표 변화로 시험합니다.
3. 목표각과 측정각을 같은 시간축에서 봅니다. 예를 들어 10° 명령에서 14°까지 갔다 돌아왔다면 초과량은 4°입니다. 이 값은 계산 예입니다. 흔들림이 크면 감쇠와 시간 간격, 계속 못 따라가면 출력 포화와 하중을 확인합니다.
4. 한 값을 바꾼 뒤 동일 입력으로 반복합니다. 지지 조건을 제거하고 바닥 접촉 상태에서도 비교합니다. 저장 후 다시 열어 설정이 적용된 레이어와 물리 백엔드가 같은지 확인하세요.
|확인 조건|기록 예시|불일치가 가리키는 곳
|관절 식별|FL_knee → 실제 왼쪽 앞무릎|USD 연결·제어기 인덱스
|각도 단위|10° ≈ 0.1745 rad|UI와 정책 설정의 변환
|위치 응답|목표·실제·최대 출력|구동기 한계·게인·부하
|재현 조건|엔진·물리 dt·초기 자세|실험 간 조건 변경
@gain Gain Tuner 사용법 |axis 단위와 좌표 규약 |phys 관절 축과 한계

## IMU 값을 읽고 뒤집힌 축을 찾아낸다
!imu-isaac_tutorial_advanced_read_imu_graph.png|OmniGraph(옴니그래프) · 공식 예제는 Angular Velocity Vector를 문자열로 바꿔 출력합니다. Read Gravity, IMU Prim, Sensor Time의 역할도 확인하세요.|imu
몸통 링크를 선택한 뒤 Create > Sensors > Imu Sensor로 추가합니다. 센서 Transform(트랜스폼)은 장착 위치와 방향입니다. 센서가 몸통을 따라 움직이는지 Play로 확인합니다. 위 그림은 빠른 표시용 재생 틱 예시입니다. 정량 비교에는 센서 시각과 물리 스텝을 함께 기록하세요.
### 세 동작만 입력해 검증하기
1. 정지 상태에서 각속도 세 축이 0 근처인지 봅니다. 가속도는 중력 포함 설정을 확인하고 해석합니다. 직립 상태의 축 한 개에서 약 9.81 m/s² 크기가 보일 수 있습니다.
2. 몸통을 한 방향으로 기울인 뒤 멈춥니다. 회전 중에만 해당 축의 각속도가 커지고 멈춘 뒤 0 근처로 돌아오는지 확인합니다. 기울어진 자세와 회전 속도를 구별하는 시험입니다.
3. 몸통 자세를 고정하고 센서 장착 방향만 바꿔 같은 움직임을 반복합니다. 세 축에 나타나는 성분이 바뀌면 프레임 정의를 기록하세요. 이 변환을 정책 전처리와 ROS 발행에서 두 번 적용하면 부호가 다시 뒤집힙니다.
로그 예시 열은 sim_time_s, frame_id, wx_rad_s, wy_rad_s, wz_rad_s, ax_m_s2, ay_m_s2, az_m_s2입니다. 첫 행에 센서 경로와 중력 포함 여부를 함께 보관합니다.

## Lab 3.0 실행 환경을 작은 예제로 확인한다
!lab-tutorial_creating_a_scene.jpg|Isaac Lab의 Interactive Scene(인터랙티브 신) 예제 결과. 같은 카트폴이 여러 위치에 복제됩니다. 장면은 Lab 코드로 구성하고 선택한 뷰어에서 관찰합니다.|lab
Git과 uv가 설치된 작업용 터미널에서 아래를 실행합니다. 이후 명령은 내려받은 IsaacLab 폴더 안에서 실행합니다. Lab 3.0은 실행 시 필요한 패키지 구성을 선택합니다. 전체 Sim 기반 실행에는 isaacsim 추가 구성이 필요합니다.
```
git clone --branch v3.0.0 --depth 1 https://github.com/isaac-sim/IsaacLab.git
cd IsaacLab
uv run isaaclab list_envs --show_presets
```
목록에서 과제 이름, 지원 물리 백엔드, viz(시각화) 조합을 확인합니다. 설치를 점검하려면 공식 Cartpole 경로로 무작위 행동을 입력해 작은 환경을 먼저 띄우세요. 첫 실행은 에셋과 의존성 준비가 필요합니다.
```
uv run isaaclab random_agent --task Isaac-Cartpole --num_envs 4 --viz newton_gl
```
여기서 선택한 Newton GL(뉴턴 GL)은 가벼운 뷰어입니다. GUI가 열렸다는 사실과 Isaac Sim의 Kit(킷) 에디터가 실행됐다는 사실을 구분하세요. 그림은 장면 생성 예제이며 위 명령의 픽셀 단위 예상 화면과는 다릅니다.

## ANYmal-D 평지 과제를 훈련하고 재생한다
!anymal.jpg|ANYmal-D(애니멀 디) 평지 환경. 평지에서 속도 추종을 먼저 검증한 뒤 경사·지형을 추가합니다. Isaac Lab v3.0.0 공식 환경 미리보기입니다.|anymal
과제 등록 이름은 Isaac-Velocity-Flat-AnymalD입니다. 3.0.0 태그의 등록 파일이 가리키는 flat_env_cfg와 rsl_rl_ppo_cfg를 함께 확인하세요. 팀에서 수정한 fork(포크)라면 실행한 커밋과 기본 설정도 남깁니다.
### Windows PowerShell 예시
같은 PowerShell 세션에서 아래 줄을 순서대로 실행하세요. --help와 과제 목록으로 지원 옵션을 확인합니다. 이 예시는 Isaac Sim PhysX(피직스)로 훈련하고, 저장된 정책을 Kit 화면에서 재생합니다. 작은 환경 수는 연결 확인용입니다.
```
$task = "Isaac-Velocity-Flat-AnymalD"
uv run --extra isaacsim isaaclab train --task $task --help
uv run --extra isaacsim isaaclab train --task $task --rl_library rsl_rl --num_envs 16 physics=isaacsim_physx
uv run --extra isaacsim isaaclab play --task $task --rl_library rsl_rl --checkpoint latest --num_envs 1 --viz kit physics=isaacsim_physx
```
훈련 명령이 종료되고 체크포인트가 저장된 뒤 play를 실행합니다. 재현 시험에서는 latest 대신 실제 체크포인트 경로를 남기세요. 훈련한 엔진, 정책 입력, 구동기와 다른 조합을 쓰면 결과가 달라질 수 있습니다.

## 내 로봇으로 옮기기 전 정책 입출력을 대조한다
체크포인트(Checkpoint)는 정책 파라미터를 담지만, 입력 벡터의 의미까지 로봇 모델에 맞춰 주지는 않습니다. 기준 모델에서 출력이 정상임을 확인한 뒤 팀 로봇의 이름·축·자유도와 비교하세요. 외형만 교체해도 링크 질량과 접촉점이 달라질 수 있습니다.
|대조 항목|훈련 설정에서 가져올 값|Sim 재생에서 확인할 것
|관측|항목 순서·단위·정규화·이전 행동|같은 초기 자세에서 첫 관측 벡터 비교
|행동|관절 이름 순서·scale·offset·제한|한 인덱스가 예상한 다리만 구동하는지 확인
|동역학|질량·마찰·출력 한계·기본 자세|정지와 한 관절 응답부터 비교
|주기|물리 dt와 제어 decimation|센서와 정책이 같은 시점의 상태를 쓰는지 확인
### 숫자로 추적하는 방법
예를 들어 위치 제어에서 목표 = 기본각 + 행동 × 스케일이라고 정의했다면 기본각 0.4 rad, 행동 −0.5, 스케일 0.2 rad에서 목표는 0.3 rad입니다. 이는 설명용 식입니다. 실제 정책에서 기본각을 포함하는지와 제한 적용 순서를 설정에서 확인합니다. 물리 0.005초에 네 스텝마다 정책을 실행하는 예라면 제어는 0.020초, 즉 50 Hz입니다.
### 실패 원인을 좁히는 순서
첫 틱에 무너지면 t=0 전후 한 프레임의 기본 자세·관절 순서·행동 변환부터 비교합니다. 몇 초 후 균형을 잃으면 접촉 시각, 출력 포화, 지연, 누적 자세 오차를 봅니다. 속도 명령만 무시하면 명령 프레임·스케일, ROS 수신 이후 정책 관측까지의 경로를 추적합니다.
### 합격 조건 예시
정지 2초 → 전진 0.5 m/s 10초 → 정지 3초를 한 시험으로 정의합니다. 넘어지면 시각과 원인을 남기고, 성공한 시도만 평균내지 않도록 전체 시도 수를 기록합니다. 평가용 지형과 시드는 학습에 쓴 조합과 따로 보관합니다.

## ROS 2와 RViz로 센서가 밖까지 도달했는지 확인한다
!rviz-official.png|RViz(알비즈) 공식 시작 화면. 왼쪽 Displays에서 Fixed Frame과 상태를 확인합니다. 그림의 No tf data는 좌표 변환 데이터가 없는 초기 상태입니다.|rviz
운영체제별 ROS 2 환경을 먼저 설정합니다. Sim의 Window > Examples > Robotics Examples에서 ROS2 > Navigation > Nova Carter를 열고 Play합니다. 설치한 워크스페이스와 ROS 배포판에 맞는 공식 launch 절차를 사용하세요. Linux와 Windows Pixi(픽시) 환경의 실행 접두사가 다릅니다.
```
ros2 topic list
ros2 topic info -v /scan
ros2 topic hz /scan
```
/scan은 예시 이름입니다. 첫 명령의 실제 namespace를 포함한 토픽으로 바꿉니다. 센서 값이 발행되면 RViz에서 Add로 LaserScan 또는 PointCloud2를 추가하고 같은 토픽을 선택합니다. 데이터가 와도 Fixed Frame에서 센서까지 TF 경로가 이어지지 않으면 화면에 점이 보이지 않습니다.
### 지도는 뜨는데 주행하지 않을 때
초기 위치를 2D Pose Estimate로 지정하고 Nav2(내브 투) 목표를 보냅니다. 속도 명령 발행 → Sim에서 수신 → 바퀴 또는 보행 제어기의 출력 → /odom 변화 순으로 따라갑니다. /clock과 use_sim_time, QoS, frame_id를 별도로 확인합니다. 4족 로봇은 수신한 전진·회전 명령을 보행 정책의 명령 관측으로 변환해야 합니다.

## 녹화와 회귀 시험으로 변경 전후를 비교한다
같은 장면에서 게인을 조정했을 때 좋아졌는지 판단하려면 성공 장면과 실패 장면의 로그가 모두 필요합니다. ROS bag(로스 백)으로 토픽을 기록하고, 정책 관측·행동처럼 외부로 발행하지 않는 값은 별도 파일에 동기화합니다.
### ROS 터미널에서 기록하고 확인하기
토픽과 타입을 확인한 후 아래 예시의 이름을 실제 장면에 맞추세요. 주행 전부터 기록하고 종료 후 Ctrl+C로 닫습니다. 되감기 시험은 제어 명령이 실물로 연결되지 않은 별도의 시뮬레이션 세션에서 수행합니다.
```
ros2 bag record -o walk_run_01 /clock /cmd_vel /odom /joint_states /tf /tf_static
ros2 bag info walk_run_01
```
|시험|남길 값|해석
|전진 추종|명령 구간의 평균 절대 오차, 단위 m/s|각 표본에서 몸체 전방 속도와 목표의 차이 절댓값을 평균
|안정성|전체 시도, 넘어짐, 최초 실패 시각|실패한 시도에도 원인 코드와 로그 경로 부여
|관절 부하|목표·실제 각도, 출력 한계 도달 시간|접촉 구간의 지연과 지속 포화를 구분
|실행 비용|가상 시간 ÷ 실제 시간, 센서 수신 주기|카메라와 기록기를 하나씩 활성화해 비교
### 시험 한 건의 인계 양식
Run ID / 날짜 / 로봇 USD·의존 파일 / Sim·Lab 버전 / task ID / 엔진 / 물리·제어 dt / checkpoint / seed / 지형·마찰 / 명령 파일 / 성공 판정 / bag과 로그 위치 / 변경 변수. 센서 시간과 시스템 시간을 명시하고, 가속도·각도·속도 열에 단위를 포함하세요.
예를 들어 가상 10초가 실제 15초 걸렸다면 실시간 배율은 약 0.67입니다. 창의 FPS만 보고 센서가 누락됐다고 판단하지 말고, 기록된 시각 간격과 메시지 개수를 같이 비교합니다.

## 카메라 데이터를 넘기고 팀 시험을 마친다
순찰 현장에서 박스 인식까지 시험한다면 보행 정책과 카메라 모델의 평가 자료가 각각 필요합니다. Replicator(리플리케이터)의 Synthetic Data Recorder(합성 데이터 기록기)를 사용하면 RGB와 분할 마스크, 경계 상자 등 같은 프레임의 정답을 저장할 수 있습니다.
### 작은 배치로 먼저 판독하기
1. 상자 한 개에 semantic label(시맨틱 레이블, 의미 라벨)을 지정하고 고정 카메라를 놓습니다. Recorder에서 카메라 경로, 해상도, writer, 출력 위치, 필요한 주석을 선택합니다.
2. 열 장 정도를 먼저 저장하고 첫·중간·마지막 프레임에서 마스크나 상자를 RGB에 겹쳐 확인합니다. 빈 정답이면 라벨·카메라 가시성·annotator부터 살핍니다. RGB와 라벨의 파일 번호와 카메라 경로를 짝지어 둡니다.
3. 조명만 바꾼 뒤 가림·배경·카메라 자세를 차례로 추가합니다. 동일한 연속 프레임을 무작위로 나누기보다 다른 배경·상자 모델을 평가용으로 보관합니다. 결과를 실물 영상에 대조할 때는 촬영 시각·렌즈·노출도 남깁니다.

|Lab CLI|관측·행동 정의, 학습, 재생|과제 설정, 체크포인트, 재생 명령
|ROS 2 / RViz|외부 센서·제어 데이터 전달과 시각화|토픽·프레임 목록, bag, RViz 설정
|Replicator|합성 이미지와 정답 작성|라벨 정의, 카메라 설정, 검수 샘플

다른 폴더에서 USD를 열고, 기록한 명령으로 정확한 체크포인트를 재생하고, 센서 한 프레임을 ROS에서 읽습니다. 세 단계 중 어디에서 실패했는지 남기면 모델 파일 누락과 제어기·센서 오류를 다음 담당자가 구별할 수 있습니다.
