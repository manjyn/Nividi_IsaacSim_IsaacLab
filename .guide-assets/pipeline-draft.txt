# 4족 순찰 로봇 개발 파이프라인
## 한 번의 순찰을 두 가지 흐름으로 읽기
공장 입구 A에서 점검 지점 B까지 걸어가고, 길이 막히면 멈추거나 우회하는 로봇을 만듭니다. 목표는 화면에서 걷는 장면 한 번을 보는 데서 시작해, 같은 시험을 동료가 재현하고 실물에서 생긴 차이까지 설명할 수 있게 하는 것입니다.
### 만드는 순서
요구사항 → 로봇·현장 모델 → 관절·센서 검증 → 보행 학습 → 경로 계획과 통합 → 가상 인수 시험 → 실물 이관 → 현장 운영. 각 화살표에서 파일과 함께 단위·기준 좌표·합격 기준을 넘깁니다.
### 실제로 움직이는 순서
운영자 목표 B → 현재 위치 추정 → 경로와 목표 속도 → 보행 정책 → 관절 목표 → 구동기 → 발과 바닥의 접촉 → 센서 측정. 센서 결과가 다음 순간의 위치 추정과 정책 입력으로 되돌아옵니다. 학습 때는 정책 가중치가 변하고 순찰 때는 저장된 정책으로 행동을 계산합니다.
### 도구별로 처음 성공시켜 볼 일
Isaac Sim(아이작 심)에서는 큐브를 떨어뜨려 바닥에 멈추게 합니다. Isaac Lab(아이작 랩)에서는 배포된 작은 환경을 실행해 관측과 행동이 오가는지 확인합니다. RViz(알비즈)에서는 로봇 앞에 둔 한 물체를 센서 좌표로 찾습니다. Unity(유니티) 운영 앱을 만든다면 실측 상태 한 건을 받아 모델 위치를 갱신합니다.
### 읽는 방법
실물 없이도 2~9장의 가상 시험을 진행할 수 있습니다. 명령 예시는 해당 페이지에 표시한 셸과 설치 구성을 따릅니다. 시험 수치·로그·판정표는 교육용 예이며 측정된 성능이나 현장 운용 한계가 아닙니다. 영문 용어는 함께 제공된 용어집에서 검색하세요.

## 현장 요청을 시험 문장으로 바꾸기
입력은 “로봇으로 야간 순찰을 하고 싶다”는 요청입니다. 먼저 운영자가 하는 일, 로봇이 결정할 일, 사람이 개입해야 할 조건을 나눕니다. 지도에서 목표점을 찍는 기능과 젖은 바닥에서 균형을 잡는 기능은 각각 다른 시험이 필요합니다.
### 직접 작성할 시험 카드
1. 시작 조건을 적습니다. 예를 들어 건조한 평지에서 네 발이 닿은 자세로 시작하고 목표 지점은 5 m 전방에 둡니다. 지도 원점과 로봇의 초기 방향을 그림으로 남깁니다.
2. 입력을 시간 순서로 적습니다. 정지 2초, 전진 0.5 m/s로 10초, 다시 정지 3초입니다. 이 시험은 보행을 확인합니다. 다음 시험에서만 경로 중간에 상자를 놓고 “감지→감속→정지 또는 우회”를 확인합니다.
3. 판정에 쓸 신호를 고릅니다. 명령 속도와 측정 속도의 차이, 몸통이 넘어진 횟수, 목표점까지의 거리, 정지 명령 이후 이동 거리입니다. 속도 오차는 출발 과도구간을 포함할지 먼저 정합니다.
4. 재시도·실패의 정의를 씁니다. 넘어져 자동 초기화되면 실패 1회로 기록합니다. 통신 끊김, 장애물 앞 정지, 경로 탐색 실패를 서로 다른 결과로 분류합니다.
### 완료와 인계
시험 번호 WALK-01에는 거리·시간·지형·초기 자세를, NAV-01에는 지도·목표점·장애물 위치를 저장합니다. 성공 기준은 담당자와 합의해 수치화합니다. 나중에 지면이나 목표 속도를 바꿀 때 어떤 시험과 비교할지 여기서 결정됩니다.

## 개발 환경을 준비하고 기준 장면 만들기
입력은 Windows 11 워크스테이션과 버전 기록입니다. Sim 6.2.0, Lab 3.0.0, GPU와 드라이버 버전을 시험 카드에 적습니다. Sim에서 3D 장면을 실행하는 시험과 Lab 의존성을 설치하는 시험을 차례로 진행하면 실패 위치가 분명해집니다.
### Sim에서 첫 기준점 만들기
1. 6.2.0 요구 사항을 확인한 뒤 워크스테이션 설치 안내를 따릅니다. Windows 명령 프롬프트에서 설치 폴더로 이동해 isaac-sim.bat를 실행합니다. 첫 장면을 불러오는 동안의 메시지는 Console(콘솔)에서 확인합니다.
2. File > New로 장면을 열고 Create > Physics > Ground Plane, Create > Shape > Cube를 선택합니다. 큐브 중심의 Z를 2 m로 올려 재생해 봅니다. 빛이 없으면 Distant Light를 추가합니다.
3. Stop 후 큐브의 Property > Add > Physics > Rigid Body with Colliders Preset을 적용하고 다시 Play합니다. 이제 낙하 후 정지해야 합니다. 장면을 저장하고 재개방해 결과가 같은지 봅니다.
### Lab 환경 열기
Git과 uv가 설치된 터미널에서 아래를 실행합니다. 과제 목록 출력은 설치 확인이고, 실제 시뮬레이터 실행은 6장에서 확인합니다.
>git clone --branch v3.0.0 --depth 1 https://github.com/isaac-sim/IsaacLab.git
>cd IsaacLab
>uv run isaaclab list_envs --show_presets
### 완료와 인계
cube_drop.usd, 설치 경로, 배포 버전, 실행 셸을 기록합니다. 큐브가 멈추지 않으면 바닥의 충돌과 큐브의 강체를 검사하고, 모델 파일만 보이지 않으면 에셋 접근 경로를 검사합니다.

## 기구 설계를 가상 로봇으로 옮기기
준비할 자료는 로봇 모델 파일, 관절 이름·축·한계, 실제 링크 길이와 질량, 센서 장착 위치입니다. 자체 모델이 없으면 배포된 예제로 흐름을 익힙니다. 모델 가져오기는 공식 UR10 로봇팔로 연습할 수 있으며, 보행 학습에는 공식 ANYmal-D 모델을 사용합니다.
### 장면을 구성하는 순서
1. File > Import에서 URDF를 선택합니다. 외부 메시 경로와 USD Output을 확인합니다. 로봇팔은 작업대에 고정될 수 있고 순찰 로봇의 몸통은 자유롭게 움직여야 합니다.
2. 알려진 링크 길이를 재 봅니다. 설계상 300 mm인 구간이 Sim에서 0.3 m인지 확인합니다. 시각 메시와 충돌체를 번갈아 표시하고, 발 충돌체가 발바닥과 맞는지 봅니다.
3. robot.usd와 warehouse.usd를 따로 관리하고 test.usda에서 참조합니다. 시험용 경사도나 센서 위치는 별도 레이어에 작성합니다. Stage 전체를 flatten하면 외부 원본의 변경이 이미 내보낸 속성에 자동 전파되지 않습니다.
4. 빈 시험장을 다른 폴더에서 다시 엽니다. 외형, 충돌체, 관절 트리, 외부 텍스처를 확인합니다. 전달 파일의 누락을 찾는 간단한 시험입니다.
### 완료와 인계
관절 대응표의 열은 “실물 이름 / USD 경로 / 정책 인덱스 / 양의 회전 방향 / 제한 단위”로 정합니다. 앞왼쪽 무릎을 움직였는데 뒤쪽 다리가 반응하면 대응표부터 수정합니다. 여러 관절을 한꺼번에 움직이면 원인을 놓치기 쉽습니다.

## 관절과 센서를 한 부위씩 검증하기
몸통과 허벅지, 정강이는 각자 질량을 가진 링크입니다. 무릎은 두 링크가 지정한 축을 중심으로 회전하도록 합니다. 몸통을 지지하는 시험과 발이 바닥을 디디는 시험을 분리하면 기구 오류와 접촉 오류를 구별할 수 있습니다.
### 관절 시험
Tools > Robotics > Asset Editors > Gain Tuner를 엽니다. 한 무릎에 현재 자세에서 작은 목표 변화를 주고 실제 각도를 기록합니다. 10° 변화를 기대했는데 0.17°만 움직이면 도와 라디안 변환을 살핍니다. 반대로 움직이면 관절축과 부호를 봅니다. 목표를 넘어 흔들리면 게인과 출력 한계·시간 간격을 한 항목씩 바꿉니다.
### 센서 시험
몸통을 선택하고 Create > Sensors > Imu Sensor로 IMU를 장착합니다. 정지, 한 방향 회전, 기울인 채 정지 세 구간을 기록합니다. 회전을 멈추면 자이로 각속도는 0 근처로 돌아옵니다. 가속도는 중력 포함 설정과 기준축을 확인한 뒤 해석합니다. 발을 하나씩 들어 해당 발의 접촉 신호도 확인합니다.
### 세 종류의 시계
예시로 물리 간격 0.005초, 네 물리 스텝마다 제어하면 명령은 50 Hz로 갱신됩니다. 카메라는 별도로 25 Hz로 촬영할 수 있습니다. 물리 시각, 센서 취득 시각, 데이터 수신 시각을 구분해 저장해야 통신 지연과 계산 지연을 구별합니다.
### 완료와 인계
명령과 실제 각도를 겹친 그래프, 센서 장착 프레임, 가속도 단위, 중력 포함 여부를 다음 담당자에게 줍니다. 정지 자세와 한 축 회전을 표시한 짧은 로그가 올바른 보행 입력을 정의하는 기준이 됩니다.

## 한 제어 스텝에서 보행 정책 읽기
속도 명령은 “앞으로 0.5 m/s”라는 요구입니다. 정책은 현재 몸통 각속도와 기울기, 관절 상태 등 과제에서 정한 관측을 읽고 행동을 냅니다. 구동기는 그 행동을 해석해 다음 물리 스텝에 적용합니다.
### 종이에 먼저 계산하기
예시로 정책 행동이 기본 관절각의 변화량을 뜻한다고 가정합니다. 기본각 0.40 rad, 정규화된 행동 −0.5, 행동 스케일 0.20 rad이면 목표각은 0.40 + (−0.5 × 0.20) = 0.30 rad입니다. 출력이 곧 토크인 과제라면 이 변환을 적용하지 않습니다. 해당 과제의 action 설정을 읽으세요.
### 학습 때 일어나는 일
1. 한 환경에서 관측→행동→물리 계산→새 상태 순으로 진행합니다. 목표 속도를 잘 따라가면 양의 보상을, 넘어지거나 명령이 급격히 변하면 설정한 비용을 받게 합니다.
2. 같은 환경을 여러 개 만들어 지면과 시작 자세를 바꾸며 경험을 모읍니다. 예를 들어 환경 16개·관절 12개라면 관절 위치 배열은 [16, 12]입니다. 한 행은 로봇 하나, 한 열은 같은 관절입니다.
3. 알고리즘이 경험을 이용해 정책을 갱신합니다. 종료된 환경만 초기화해 다음 에피소드를 시작합니다. 재생 때는 학습된 정책으로 행동을 계산합니다.
### 첫 실행과 판정
IsaacLab 폴더에서 다음 명령으로 등록된 Cartpole 환경을 열어봅니다. 카트 위 막대가 움직이면 기본 실행 경로가 연결된 것입니다. 무작위 행동이므로 균형 유지 여부는 성공 기준이 아닙니다.
>uv run isaaclab random_agent --task Isaac-Cartpole --num_envs 4 --viz newton_gl

## 기준 보행을 훈련하고 체크포인트 재생하기
기준 과제의 이름은 Isaac-Velocity-Flat-AnymalD입니다. 팀 로봇을 연결하기 전에 수정 없는 공식 과제에서 학습과 재생의 한 쌍을 확인하세요. 아래는 IsaacLab 폴더에서 실행하는 Windows PowerShell 예시입니다. 필요한 GPU·설치 구성은 Lab 3.0 문서를 따릅니다.
>$task = 'Isaac-Velocity-Flat-AnymalD'
>uv run --extra isaacsim isaaclab train --task $task --help
>uv run --extra isaacsim isaaclab train --task $task --rl_library rsl_rl --num_envs 16 physics=isaacsim_physx
>uv run --extra isaacsim isaaclab play --task $task --rl_library rsl_rl --checkpoint latest --num_envs 1 --viz kit physics=isaacsim_physx
훈련이 체크포인트를 저장한 뒤 마지막 줄을 실행합니다. 16개 환경은 실행 확인용 예시입니다. 같은 실험을 다시 재생할 때는 latest 대신 선택한 파일 경로를 기록하세요. 영상이 뜨는지, 명령이 관측에 들어가는지, 목표 관절과 실제 관절이 맞는지를 따로 확인합니다.
### 숫자가 좋아져도 확인할 것
누적 보상이 올랐는데 걷지 않는다면 보상 항목별 기여도를 봅니다. 정지 보상이 큰지, 목표 속도 자체가 0으로 들어가는지, 넘어지자마자 초기화되는지를 구분합니다. 훈련에 쓰지 않은 마찰·하중·시드에서 완주율과 속도 오차를 측정합니다.
### 완료와 인계
체크포인트, task ID, 커밋, 관측 항목 순서, 정규화 통계, 행동 크기·오프셋, 기본 관절각, 물리·제어 주기를 한 묶음으로 넘깁니다. 체크포인트를 여는 데 성공해도 입력의 뜻이나 관절 순서가 달라지면 움직임이 달라집니다.

## ROS 2로 목적지와 보행을 연결하기
Nav2(내브 투)는 지도와 장애물을 바탕으로 이동 경로와 속도 명령을 계산할 수 있습니다. 보행 정책은 이 속도 명령과 몸 상태를 사용해 관절 목표를 냅니다. 둘 사이의 계약은 “어느 좌표계에서, 어떤 단위로, 몇 초까지 유효한 명령인가”입니다.
### 통신부터 한 단계씩 확인
1. 운영체제에 맞는 ROS 2 환경과 Sim 브리지를 준비합니다. Window > Examples > Robotics Examples에서 ROS2 > Navigation > Nova Carter 예제를 엽니다. Play 후 공식 launch 절차를 따릅니다. 바퀴 로봇으로 지도·센서·연결을 먼저 확인하는 실습입니다.
2. ROS 환경을 적용한 터미널에서 아래 명령을 실행합니다. /scan은 발견한 실제 토픽 이름으로 바꿉니다. RViz에서 지도와 센서가 같은 위치에 보이려면 센서 frame_id에서 Fixed Frame까지 TF가 연결돼야 합니다.
>ros2 topic list
>ros2 topic info -v /scan
>ros2 topic hz /scan
3. 목표를 보내고 /cmd_vel 계열 명령, 몸체 속도 /odom, 이동 궤적 순으로 확인합니다. 4족 로봇에서는 명령을 학습 시의 몸체 전방·측방·회전 관측으로 변환하는 연결 코드를 둡니다. 정확한 메시지 타입과 이름은 실제 설정을 확인합니다.
### 위치가 틀릴 때 하는 한 가지 실험
로봇 전방 1 m에 물체를 놓습니다. Sim에서 보이는데 RViz의 옆에 나타나면 센서 장착 회전과 TF를 검사합니다. 좌표가 맞는데 수신이 없으면 토픽·QoS·시계를 봅니다. 속도 명령이 있는데 로봇이 멈추면 수신 이후 정책 입력과 구동기 출력을 살핍니다.

## 가상 현장 인수 시험과 실패 재현
SIL은 현장에서 쓸 제어 소프트웨어를 가상 센서·구동기에 연결하는 시험입니다. 공장 통로에서 출발, 정속, 장애물 접근, 정지까지 한 번에 실행하되 각 단계의 시간표를 기록하세요.
### 결과를 계산하는 연습
명령 0.50 m/s, 측정값 0.40·0.55·0.45 m/s라면 절대 오차 평균은 (0.10 + 0.05 + 0.05) ÷ 3 ≈ 0.067 m/s입니다. 실제 시험에서는 같은 시간격으로 맞춘 전 구간 표본을 사용합니다. 가상 시간 10초에 실제 시간 15초가 걸렸다면 실시간 배율은 0.67입니다. 두 값은 각각 보행 정확도와 계산 속도를 나타냅니다.
### 실패를 재현할 기록
ROS 환경에서 실제 토픽을 확인하고 다음과 같이 기록합니다. ROS 밖에서만 존재하는 정책 관측·행동과 실제 관절 목표는 별도 로그에 같은 시각을 붙입니다.
>ros2 bag record -o walk_01 /clock /cmd_vel /odom /joint_states /tf /tf_static
>ros2 bag info walk_01
기록을 재생하면 당시 메시지를 볼 수 있습니다. 물리 실험을 다시 실행하려면 장면·초기 상태·제어 입력·설정도 필요합니다. 실패한 시도까지 포함해 “5회 중 완주 4회, 1회는 회전 중 우측 발 미끄러짐”처럼 씁니다.
### 원인 분기
목표가 있는데 명령이 없으면 위치 추정과 계획을, 명령은 있는데 관절 목표가 없으면 정책 연결을, 목표는 정상인데 쓰러지면 접촉·게인·하중을 확인합니다. 값을 하나만 변경하고 같은 시험 번호에 새로운 실행 번호를 붙이세요.
@perf 성능 측정|nav 주행 예제|deploy 배포 시험

## 실물에 연결하고 운영 결과를 개발로 돌려보내기
실물에 넘기는 것은 로봇 상태를 읽는 코드, 정책 입력 변환, 정책 파일, 모터 명령 변환, 정지 동작과 버전 기록입니다. 하드웨어 제조사의 제어 모드·제한·비상정지 절차를 기준으로 시험 범위를 정합니다. 장치를 직접 연결해 통신과 타이밍을 시험하면 HIL에 해당할 수 있습니다.
### 실물 이관을 작게 나누기
1. 모터 출력을 보내기 전 로그만 읽습니다. 실제 무릎을 움직였을 때 어떤 인덱스의 각도가 증가하는지 보고 시뮬레이션의 부호·단위와 대조합니다.
2. 지지된 자세에서 허용 범위 안의 작은 명령을 사용합니다. 목표와 측정값의 지연, 최대 출력, 정지 명령 반응을 확인합니다. 독립된 정지 수단과 감독 조건을 갖춘 뒤 운용 범위를 늘립니다.
3. 평지 저속부터 시작해 시뮬레이션과 실물에서 같은 명령 응답을 비교합니다. 마찰·하중·센서 지연 등 차이를 가정하고 한 변수씩 대조합니다. 수정된 모델은 미사용 시험 기록에서도 확인합니다.
### 운영 앱에서 보이는 것
Unity(유니티) 앱에서는 운용자가 목표를 보내고 실제 /odom·관절값을 받아 화면을 갱신할 수 있습니다. 전진 버튼으로 모델 표시 위치까지 직접 이동시키면 로봇이 미끄러져도 화면만 전진합니다. 명령·수신 확인·실측 결과를 각각 표시하세요.
### 현장 사례와 한계
NVIDIA·ETH의 공개 사례는 시뮬레이션에서 학습한 ANYmal 보행을 실물에서 실행했습니다. 다른 로봇으로 옮길 때에는 해당 로봇의 센서·구동기 계약을 다시 검증합니다. 현장 실패의 입력·지도·로그를 가상 실험으로 돌려보내고, 수정 정책이 이전 통과 시험까지 유지하는지 확인한 뒤 버전을 올립니다.

### 어떤 용어부터 찾을까
장면이 안 열리면 용어집의 Stage·Reference·Payload·Asset Root, 다리가 반대 방향으로 접히면 Joint Axis·DOF·Drive·Quaternion을 찾습니다. 학습은 되는데 재생이 다르면 Observation·Normalization·Decimation·Checkpoint를, 통신은 되는데 지도에 점이 없으면 TF·Fixed Frame·QoS·Timestamp를 확인합니다.
### 시뮬레이션 외의 응용
순찰 로봇이 박스를 인식해야 한다면 카메라 영상과 정답 라벨을 Replicator(리플리케이터)로 생성하고 실물 영상에서 평가합니다. 로봇팔에 조립을 학습시킨다면 접촉, 파지, 부품 자세 추정, 실제 제어기 연결이 추가됩니다. NVIDIA의 지게차 인식·UR10e 조립 사례는 두 갈래가 실제 프로젝트에서 쓰인 예입니다.
