## 개발 도구와 실행 환경
Isaac Sim(아이작 심)|가상 로봇·센서·현장을 실행하는 NVIDIA 시뮬레이터. 이 프로젝트의 GUI와 API 기준은 6.2.0이다.
Isaac Lab(아이작 랩)|로봇 학습 과제, 병렬 환경, 평가를 구성하는 프레임워크. 기준 버전은 3.0.0이며 선택한 백엔드에 따라 Sim 없이 실행할 수도 있다.
Omniverse(옴니버스) / Kit(킷)|Omniverse는 시뮬레이션·렌더링용 플랫폼 및 라이브러리 모음, Kit는 확장 가능한 앱을 구성하는 기반이다.
Backend(백엔드) / Preset(프리셋)|작업을 실제 수행하는 구현과 미리 묶은 설정. 과제에서 지원하는 물리·렌더·뷰어 조합을 조회한다.
PhysX(피직스) / Newton(뉴턴)|강체와 관절 운동 등을 계산하는 물리 엔진. 같은 로봇이라도 접촉 모델과 구동기 설정을 비교해야 한다.
MuJoCo(무조코) / MuJoCo Warp(무조코 워프)|물리 시뮬레이터와 Warp 기반 가속 구현. 특정 Lab 백엔드·솔버 조합에서 만난다.
Warp(워프) / CUDA(쿠다)|Warp는 물리·수치 계산용 병렬 커널을 작성하는 도구, CUDA는 NVIDIA GPU 계산 플랫폼이다.
GUI / CLI / API / SDK|화면으로 조작하는 인터페이스, 명령줄, 코드 호출 규약, 개발 도구 모음. 같은 작업도 진입점마다 초기화 절차가 다르다.
Standalone(스탠드얼론) / Headless(헤드리스)|독립 프로그램으로 실행하는 방식과 화면 창 없이 실행하는 방식. 독립 스크립트도 창을 띄울 수 있다.
Docker(도커) / Container(컨테이너)|의존성과 실행 환경을 이미지로 묶어 재사용한다. GPU 드라이버 등 호스트 조건도 기록한다.
Git(깃) / Tag(태그) / Commit(커밋)|변경 이력 관리, 버전에 붙인 이름, 특정 변경 상태. 실험 재현에는 실행한 커밋을 저장한다.
GA / Alpha(알파) / Beta(베타)|정식 공개판과 사전 공개 단계. 6.2.0은 Sim 정식판이며 앞서 다룬 7.0.0a1은 다음 구조의 첫 알파다.
uv(유브이) / Python(파이썬)|uv는 프로젝트 의존성과 실행 환경을 관리하고 Python은 Lab 과제와 Sim 자동화 코드를 작성하는 언어다.

## 에디터와 Unity 비교
Stage(스테이지)|열린 USD 장면 전체. 여러 파일의 속성과 관계를 합성해 현재 장면을 보여 준다.
Prim(프림)|장면 트리에서 경로로 식별되는 항목. /World/Robot/Camera처럼 경로를 써서 코드에서 선택한다.
Viewport(뷰포트) / Gizmo(기즈모)|장면을 보는 창과 선택 물체를 이동·회전·확대하는 화면 도구. W/E/R의 대상 좌표계를 확인한다.
Property(프로퍼티) / Content(콘텐츠)|선택한 prim의 속성 패널과 자산 파일 브라우저. 파일 원본과 현재 장면 인스턴스를 구별한다.
Timeline(타임라인) / Physics Scene(피직스 신)|재생 시간을 제어하는 도구와 중력 등 물리 월드 설정을 담는 장면 요소다.
Extension(익스텐션) / Script Editor(스크립트 에디터)|앱에 기능을 추가하는 모듈과 열린 장면에서 Python을 실행하는 창. 재사용할 기능은 확장으로 구성할 수 있다.
OmniGraph(옴니그래프) / Action Graph(액션 그래프)|노드와 연결로 데이터·실행 흐름을 표현하는 체계와 이벤트 기반 그래프. IMU 값을 ROS로 보내는 순서를 구성한다.
Unity Editor(유니티 에디터) / GameObject(게임오브젝트)|Unity 앱을 만드는 편집기와 장면 구성 단위. 관제 화면에서 로봇 표시 객체를 센서값에 맞춰 갱신할 수 있다.
Hierarchy(하이어라키) / Inspector(인스펙터)|Unity의 장면 계층 창과 선택 항목 속성 창. Sim의 Stage 트리·Property 창과 대응해 이해한다.
Prefab(프리팹) / Component(컴포넌트)|재사용하는 Unity 객체 템플릿과 객체에 붙는 기능. Prefab override는 USD 참조에 현장별 값을 덮는 개념과 닮았다.
MonoBehaviour(모노비헤이비어) / FixedUpdate(픽스드 업데이트)|Unity 이벤트 기반 스크립트와 고정 시간 간격 처리 콜백. 물리와 렌더 프레임 수가 항상 같지는 않다.
ArticulationBody(아티큘레이션 바디) / Rigidbody(리지드바디)|Unity에서 관절 기구의 링크를 나타내는 컴포넌트와 일반 강체 컴포넌트. 링크 하나와 전체 기구를 구별한다.
RenderTexture(렌더 텍스처) / EditorWindow(에디터 윈도우)|Unity 렌더 출력을 저장하는 텍스처와 사용자 정의 편집 창. 각각 센서 출력·Sim 도구 창을 이해하는 비교점이다.

## OpenUSD 자산과 합성
OpenUSD(오픈유에스디)|Pixar에서 시작한 장면 기술·합성 체계. 형상뿐 아니라 재질·관절·센서 같은 데이터를 한 장면으로 조직한다.
USD / USDA / USDC / USDZ|USD는 장면 기술의 통칭이자 확장자다. USDA는 텍스트, USDC는 바이너리, USDZ는 자산을 담는 패키지다.
Layer(레이어) / Edit Target(에디트 타깃)|값을 기록하는 장면 기술 단위와 현재 수정이 기록될 대상. 화면에서 같은 로봇을 선택해도 수정할 파일이 달라질 수 있다.
Sublayer(서브레이어) / Layer Stack(레이어 스택)|한 레이어가 다른 레이어를 쌓아 합성한다. 여러 레이어가 같은 속성을 쓰면 합성 규칙이 최종 값을 정한다.
Reference(레퍼런스) / Override(오버라이드)|원본 장면을 참조하고 배치한 위치에서 일부 속성만 덮어쓴다. 로봇을 공유하며 시험장마다 위치를 다르게 할 수 있다.
Payload(페이로드) / Variant Set(베리언트 세트)|필요한 때 로드할 수 있는 합성 대상과 선택 가능한 구성 집합. 예를 들어 같은 로봇의 센서 옵션을 전환한다.
Flatten(플래튼) / Flatten Layer Stack(플래튼 레이어 스택)|전체 Stage를 굳히면 합성된 값과 선택한 변형이 사본에 기록된다. 레이어 스택만 합치면 외부 참조 등은 유지된다.
Schema(스키마) / Attribute(애트리뷰트) / Relationship(릴레이션십)|데이터의 의미를 규정하는 형식, 값이 있는 속성, prim 등을 가리키는 관계. 관절의 연결 대상은 관계로 표현한다.
Xform(엑스폼) / Mesh(메시)|변환을 표현하는 USD 타입과 면·정점으로 이루어진 형상. 형상이 보인다는 사실만으로 충돌 반응이 정해지지 않는다.
Instancing(인스턴싱) / Asset Root(에셋 루트)|공유 원형을 여러 번 배치하는 방식과 자산 탐색의 기준 위치. 에셋 루트가 달라지면 원격 파일 해석이 실패할 수 있다.
URDF / MJCF / CAD|ROS 로봇 기술용 XML, MuJoCo 모델 기술 형식, 설계 데이터. 형식 간 변환 뒤에는 단위·관성·충돌을 다시 점검한다.
Asset Transformer(에셋 트랜스포머) / Asset Validation(에셋 밸리데이션)|규칙으로 자산을 변환하는 도구와 규칙 충족 여부를 검사하는 도구. 반복 변환과 품질 검사를 자동화한다.
Digital Twin(디지털 트윈) / NuRec(뉴렉)|실물 시스템의 상태·동작과 대응시키는 가상 모델, 실측 캡처에서 장면을 재구성하는 NVIDIA 기술. 외형과 동역학 정확도는 따로 평가한다.

## 물리와 구동기
Rigid Body(리지드 바디) / Collider(콜라이더)|변형하지 않는다고 가정한 물체와 충돌 판정 형상. 바닥과 발이 만나려면 물리 엔진이 인식하는 충돌 형상이 필요하다.
Link(링크) / Joint(조인트)|로봇의 강체 부품과 부품 사이에 허용되는 운동을 정하는 연결. 허벅지와 정강이를 무릎 관절이 잇는다.
Articulation(아티큘레이션)|관절로 연결한 링크의 운동과 힘을 함께 계산하는 구조. 발이 지면을 밀면 몸통 자세도 변할 수 있다.
DOF / Joint Axis(조인트 액시스)|독립적으로 움직일 수 있는 자유도와 그 운동의 기준축. 힌지형 무릎의 회전은 1자유도다.
Revolute(레볼루트) / Prismatic(프리즈매틱) / Fixed Joint(픽스트 조인트)|한 축 회전, 한 축 직선 이동, 상대운동 고정. 바퀴·슬라이더·고정 센서에 각각 대응한다.
Mass(매스) / Center of Mass(센터 오브 매스) / Inertia(이너셔)|질량, 질량중심, 회전 변화에 대한 저항. 같은 질량이라도 배터리 위치를 옮기면 자세 응답이 달라진다.
Friction(프릭션) / Restitution(레스티튜션)|접선 방향 미끄럼에 대한 마찰과 충돌 뒤 튀어 오르는 정도. 표시 재질과 물리 재질을 구분한다.
Contact(콘택트) / Self-Collision(셀프 컬리전)|물체 사이의 접촉과 한 로봇 내 부품끼리의 충돌. 링크 간 필터가 맞지 않으면 초기 자세에서 튈 수 있다.
Actuator(액추에이터) / Drive(드라이브)|관절에 힘을 전달하는 장치·모델과 목표를 추종하게 하는 구동 설정. 목표각과 실제 토크는 다른 물리량이다.
Torque(토크) / Effort Limit(에퍼트 리밋)|회전시키는 힘의 모멘트와 구동 출력 한계. 회전 관절 토크는 N·m, 직선 관절의 힘은 N을 쓴다.
Stiffness(스티프니스) / Damping(댐핑) / PD|위치 오차에 반응하는 강성, 속도 오차에 반응하는 감쇠, 두 항을 쓰는 제어. 과도 응답을 목표·실측 곡선으로 본다.
Gain Tuner(게인 튜너) / Overshoot(오버슈트)|관절 구동값을 조정·시험하는 도구와 목표를 지나치는 양. 정착 시간과 출력 포화도 같이 살핀다.
System Identification(시스템 아이덴티피케이션)|실물 입력·출력 기록으로 모델 매개변수를 추정하는 시스템 식별. 맞춤에 쓴 기록과 검증용 기록을 분리한다.
Solver(솔버) / Substep(서브스텝)|물리식을 수치적으로 푸는 계산기와 세분한 계산 단계. 단계 크기와 솔버 설정은 정확도·계산량에 영향을 준다.

## 좌표와 시간 그리고 상태
Frame(프레임) / Transform(트랜스폼)|좌표의 기준과 두 기준 사이 위치·회전 변환. “전방”은 로봇·세계·카메라 중 어느 기준인지 명시한다.
Pose(포즈) / Orientation(오리엔테이션)|위치와 방향을 묶은 자세, 그중 회전 방향. 같은 위치에서도 카메라는 반대쪽을 볼 수 있다.
Quaternion(쿼터니언) / Euler Angles(오일러 앵글)|회전을 나타내는 네 성분과 축별 회전각 표현. API 간 wxyz·xyzw 순서 및 오일러 회전 순서를 대조한다.
Radian(라디안) / Degree(디그리)|각도 단위. π rad = 180°이며 USD 속성의 각도와 제어 API 단위가 다를 수 있다.
Handedness(핸디드니스) / Up Axis(업 액시스)|좌표계 손잡이와 위쪽 축. Unity는 왼손·Y 위, Sim 기본 월드는 오른손·Z 위다.
Velocity(벨로시티) / Angular Velocity(앵귤러 벨로시티)|단위 시간당 위치·회전 변화. 10° 기울어진 채 정지하면 각속도는 0 근처다.
Physics dt(피직스 델타 티) / Control Rate(컨트롤 레이트)|물리 한 번의 시간과 제어 명령 갱신 빈도. dt=0.005초이면 물리는 초당 200회다.
Decimation(데시메이션)|한 정책 행동을 몇 물리 스텝 동안 유지할지 정하는 간격. 물리 200 Hz에서 4라면 정책은 50 Hz다.
Timestamp(타임스탬프) / Latency(레이턴시)|측정 시각과 전달·처리 지연. 센서 취득 시간과 메시지 수신 시간을 따로 남긴다.
Simulation Time(시뮬레이션 타임) / Wall Time(월 타임)|가상 세계에서 흐른 시간과 실제 경과시간. 일시정지나 느린 렌더에서 둘이 달라진다.
RTF / FPS / Hz|실시간 배율, 초당 렌더 프레임, 초당 반복 횟수. RTF 0.5는 실제 2초에 가상 1초가 흐른다는 뜻이다.
Encoder(엔코더) / State Estimation(스테이트 에스티메이션)|관절·축의 움직임을 측정하는 장치와 여러 센서로 몸 상태를 추정하는 과정. 관절값만으로 전역 위치가 바로 나오지는 않는다.

## 센서와 영상
IMU|Inertial Measurement Unit, 관성 측정 장치. 보통 3축 가속도계와 3축 자이로를 갖추고 몸통 움직임을 측정한다.
Accelerometer(액셀러로미터) / Gyroscope(자이로스코프)|가속도계와 각속도계. 정지 가속도는 중력 포함 설정과 프레임을 확인해 해석한다.
LiDAR(라이다) / Point Cloud(포인트 클라우드)|광선으로 거리를 측정하는 센서와 얻은 점들의 집합. 한 스캔의 시간 폭도 이동 중 형상에 영향을 줄 수 있다.
Radar(레이더) / Acoustic Sensor(어쿠스틱 센서)|전파·음향을 사용하는 감지 방식. 재질의 가시광 색만으로 센서 반응을 결정할 수 없다.
RGB / Depth(뎁스)|색 영상과 깊이. 광축 방향 깊이인지 광선을 따라 잰 거리인지 정의를 확인해야 한다.
Intrinsics(인트린식스) / Extrinsics(엑스트린식스)|초점거리·주점 등 카메라 내부 파라미터와 장착 위치·회전. 픽셀을 로봇 좌표로 옮길 때 둘 다 필요하다.
Calibration(캘리브레이션) / Noise(노이즈) / Bias(바이어스)|측정 모델 보정, 무작위 변동, 일정하거나 천천히 변하는 치우침. 정지 구간에서 평균과 분산을 나눠 본다.
Contact Sensor(콘택트 센서) / Effort Sensor(에퍼트 센서)|발 등의 접촉과 관절의 힘·토크를 관측한다. 값의 대상 링크, 단위, 샘플 시각을 함께 기록한다.
Raycast(레이캐스트)|광선과 장면 형상의 교차점을 구하는 질의. 단발 레이캐스트와 회전식 센서 전체 스캔의 동작이 다르다.
Render Product(렌더 프로덕트) / RTX|카메라·해상도 등 출력 설정을 묶은 렌더 대상과 NVIDIA의 광선 추적 관련 기술. 카메라 prim만 생성해도 출력 파일이 자동 저장되는 것은 아니다.
Clipping(클리핑) / Field of View(필드 오브 뷰)|보이는 거리 범위의 절단과 시야각. 가까운 벽이 사라지면 최소 거리와 카메라 장착 위치를 점검한다.
Path Tracing(패스 트레이싱) / Real-time Rendering(리얼타임 렌더링)|광 경로를 추적해 영상을 만드는 방식과 상호작용을 위한 렌더 방식. 품질과 처리 시간을 같은 조건에서 비교한다.

## 학습 과제와 알고리즘
Task(태스크) / Environment(인바이런먼트)|해결할 과제와 에이전트가 상호작용하는 환경. task ID는 모델·관측·보상·등록 설정을 찾는 출발점이다.
Agent(에이전트) / Policy(폴리시)|행동 주체와 관측을 행동으로 바꾸는 규칙·모델. 한 에이전트의 정책을 여러 가상 로봇에서 동시에 평가할 수 있다.
Observation(옵저베이션) / State(스테이트)|정책이 받는 입력과 시스템의 상태. 시뮬레이터가 아는 참값 중 실물에서 얻을 수 없는 값은 정책 배포 시 문제가 된다.
Action(액션) / Action Space(액션 스페이스)|정책이 내는 값과 가능한 행동의 범위. 정책 숫자 1이 1 rad인지 정규화된 최대 명령인지 확인한다.
Reward(리워드) / Return(리턴)|한 스텝의 보상과 여러 스텝의 보상 누적값. 보상이 커져도 실제 주행 성능은 별도 지표로 본다.
Episode(에피소드) / Reset(리셋)|초기 상태부터 종료까지 한 시도와 다음 시도 준비. 낙상과 시간 제한 종료를 구분해 기록한다.
Termination(터미네이션) / Truncation(트렁케이션)|과제의 종료 조건 달성과 외부 시간 제한 등으로 중단되는 경우. 학습 타깃과 평가 집계에 영향을 준다.
MDP / RL|현재 상태·행동에서 다음 상태와 보상을 정의하는 마르코프 결정 과정, 경험으로 정책을 학습하는 강화학습.
PPO / Actor–Critic(액터 크리틱)|PPO는 정책 갱신 폭을 제어하는 계열의 알고리즘. 액터는 행동을 내고 크리틱은 기대 성과를 추정한다.
RSL-RL / skrl / RL-Games|Lab 과제와 연결할 수 있는 학습 라이브러리 예시. 같은 과제라도 설정 파일과 체크포인트 형식이 다를 수 있다.
Rollout(롤아웃) / Batch(배치)|정책을 실행하며 모은 경험 궤적과 한 번에 처리하는 데이터 묶음. 환경 수와 스텝 수를 기록한다.
Inference(인퍼런스) / Checkpoint(체크포인트)|학습된 정책으로 행동을 계산하는 추론과 저장된 학습 상태. latest 대신 사용한 파일을 특정해야 재현된다.
Imitation Learning(이미테이션 러닝) / Teleoperation(텔레오퍼레이션)|사람 등의 시연을 이용한 모방학습과 원격 조작. 시연 데이터에 관측·행동의 시간 대응이 필요하다.

## 학습 데이터와 배포 계약
Tensor(텐서) / Shape(셰이프)|여러 축으로 구성된 수치 배열과 축별 길이. [환경 수, 관절 수]에서 왼쪽 무릎을 고르려면 열 인덱스를 찾는다.
Device(디바이스) / Dtype(디타입)|데이터가 있는 계산 장치와 숫자 자료형. CPU·GPU 간 왕복 복사와 형 변환이 실행에 영향을 준다.

Domain Randomization(도메인 랜더마이제이션)|마찰·하중·센서 오차 등을 분포에서 뽑아 훈련한다. 범위는 실물 변동과 시험 목적에 맞춘다.
Curriculum(커리큘럼) / Seed(시드)|학습 중 난이도를 바꾸는 전략과 난수 초기값. 평가에는 별도 시드와 조건을 둔다.
Sim-to-Sim(심투심) / Sim-to-Real(심투리얼)|다른 시뮬레이션 환경에서 동작을 비교하거나 실물로 이관하는 과정. 입출력 차이와 물리 차이를 단계별로 분리한다.
Reality Gap(리얼리티 갭)|가상과 실물의 차이. 관절 마찰·전달 지연·발 재질 등 관측 가능한 원인으로 쪼개어 검증한다.

## ROS 통신과 좌표
ROS 2 / Node(노드)|로봇 프로그램 간 통신 생태계와 실행 단위. 위치 추정·속도 제어를 서로 다른 노드가 담당할 수 있다.
Topic(토픽) / Message(메시지)|연속 데이터를 주고받는 이름 있는 통로와 그 자료 구조. 같은 이름뿐 아니라 메시지 타입도 확인한다.
Publisher(퍼블리셔) / Subscriber(서브스크라이버)|데이터 발행자와 구독자. 센서에서 발행해도 수신 측 설정이 맞아야 표시된다.

QoS / Namespace(네임스페이스)|신뢰성·보관 등 전달 정책과 이름의 범위. 로봇 두 대가 같은 토픽을 덮어쓰는 문제를 이름으로 구분한다.
Bridge(브리지) / ROS-TCP-Endpoint(엔드포인트)|시뮬레이터나 Unity와 ROS 사이에서 메시지를 연결하는 구성. Unity 연결에는 호환되는 ROS 측 엔드포인트가 필요하다.
TF / frame_id / Fixed Frame(픽스트 프레임)|프레임 간 변환 체계, 메시지 좌표계 표식, RViz의 표시 기준 프레임. 시간도 맞아야 변환할 수 있다.
/clock / use_sim_time|가상 시간 발행과 ROS 노드가 해당 시계를 쓰도록 하는 설정. 서로 다른 시계로 기록하면 센서 동기화가 틀어진다.
/cmd_vel / Twist(트위스트)|관례적인 속도 명령 토픽과 선속도·각속도 정보. 프로젝트에서 실제 메시지 타입·프레임을 확인한다.
/odom / Odometry(오도메트리)|상대 이동으로 추정한 자세·속도 및 관련 토픽. 오차가 누적될 수 있어 지도상의 절대 위치와 구별한다.

rosbag(로스백) / Replay(리플레이)|메시지 기록과 재생. 당시 통신은 재생할 수 있지만 물리 시험 재현에는 초기 상태와 제어 설정도 필요하다.

Occupancy Map(오큐펀시 맵) / Costmap(코스트맵)|점유·빈 공간 추정 지도와 이동 위험·비용을 부여한 지도. 장애물 주변 여유 거리를 계획에 반영한다.
Path(패스) / Trajectory(트래젝터리)|공간상 지나야 할 경로와 시간 정보가 붙은 움직임. 같은 경로라도 속도에 따라 관절 부하가 다르다.
Planner(플래너) / Controller(컨트롤러)|경로·동작 계획을 만드는 부분과 목표를 따르기 위한 명령을 갱신하는 부분. 위치 오차와 관절 오차를 구별한다.
Waypoint(웨이포인트) / Goal(골)|경유 지점과 도달 목표. 지도 좌표와 허용 위치·방향 오차를 같이 정한다.
AMCL|지도와 거리 관측을 이용해 입자 필터 방식으로 위치를 추정하는 알고리즘. 초기 위치 추정값을 RViz에서 지정할 수 있다.
Differential Drive(디퍼렌셜 드라이브) / Ackermann(애커먼)|좌우 바퀴 속도 차 구동과 자동차형 조향. 4족 로봇은 속도 명령을 보행 제어기로 전달한다.
FK / IK|관절값으로 끝단 자세를 계산하는 순기구학과 목표 자세에서 관절값을 구하는 역기구학. IK 해가 곧 충돌 없는 경로를 보장하지 않는다.
MoveIt 2(무브잇 투) / cuMotion(큐모션)|로봇팔 계획·실행을 위한 ROS 도구와 NVIDIA 모션 생성 기술. 장애물·관절 한계·그리퍼 동작을 함께 시험한다.

## 비전과 합성 데이터
Replicator(리플리케이터) / SDG|장면 또는 센서 조건을 바꾸며 데이터와 정답을 생성하는 도구와 합성 데이터 생성 작업이다.
Semantic Label(시맨틱 레이블)|객체에 붙인 의미 라벨. 예를 들어 여러 상자의 클래스 이름을 box로 정하면 클래스 분할 자료를 만들 수 있다.
Semantic Segmentation(시맨틱 세그멘테이션) / Instance Segmentation(인스턴스 세그멘테이션)|픽셀별 클래스 분류와 같은 클래스 안의 개별 객체 구분. 상자 두 개에 같은 색을 줄지 다른 ID를 줄지의 차이다.
Bounding Box(바운딩 박스) / Mask(마스크)|객체를 둘러싸는 상자와 픽셀 단위 영역. RGB 위에 겹쳐 가림·누락을 확인한다.
Annotator(애너테이터) / Writer(라이터)|렌더 결과에서 원하는 정답 항목을 얻는 기능과 파일 형식에 맞춰 저장하는 기능. 출력 번호와 카메라 ID를 연결한다.
Ground Truth(그라운드 트루스)|평가 기준이 되는 참값. Sim이 아는 정확한 자세는 평가에 유용하지만 정책이 실물에서 볼 수 있는 입력인지 확인한다.
Occlusion(어클루전) / Augmentation(오그멘테이션)|가림과 데이터 변형. 일부만 보이는 상자도 학습·평가 조건에 포함한다.
Train / Validation / Test Split(트레인·밸리데이션·테스트 스플릿)|학습·모델 선택·최종 평가용 데이터 분할. 같은 영상의 인접 프레임이 다른 세트에 섞이면 결과가 과대평가될 수 있다.
FoundationPose(파운데이션 포즈) / Isaac ROS(아이작 로스)|객체 자세 추정 기술과 로봇용 가속 패키지 모음. 실물 조립에서는 가상 참값 대신 카메라 기반 추정값을 제어에 전달한다.
TAO Toolkit(타오 툴킷) / Jetson(젯슨)|모델 훈련·적응을 위한 NVIDIA 도구와 엣지 컴퓨팅 플랫폼. 지게차 공개 사례는 합성 이미지에서 훈련해 엣지에서 추론했다.
MobilityGen(모빌리티젠) / Cosmos(코스모스)|이동 로봇 데이터 생성 워크플로와 NVIDIA 월드 모델 플랫폼. 활용 범위는 주행 기록 생성과 장면 데이터 확장 등으로 구분한다.
Sensing Material(센싱 머티리얼) / Physics Material(피직스 머티리얼)|센서 파장·모델의 반응에 쓰는 재질 정보와 마찰·반발 계수 등 물리 재질. 색을 바꿔도 마찰이 자동 변하지 않는다.

## 실험과 운영 인계
SIL / HIL|Software-in-the-loop와 Hardware-in-the-loop. 실제 제어 소프트웨어에 가상 로봇을 붙이는 시험과 실제 장치를 루프에 넣어 타이밍까지 검사하는 시험이다.
Baseline(베이스라인) / Regression Test(리그레션 테스트)|비교 기준이 되는 실행과 수정 이후 이전 기능이 유지되는지 보는 회귀 시험. 같은 장면·시드·초기 자세를 남긴다.
MAE / RMSE|평균 절대 오차와 평균 제곱 오차의 제곱근. RMSE는 큰 오차의 영향을 더 받는다. 단위와 평가 시간창을 기록한다.
Success Rate(석세스 레이트) / Failure Mode(페일리어 모드)|전체 시도 중 성공 비율과 실패 형태. 재설정된 시도까지 분모에 포함해 낙상·미도달·충돌을 구분한다.
Tracking Error(트래킹 에러) / Settling Time(세틀링 타임)|목표와 실제 응답의 차이, 목표 주변 허용 범위에 들어와 머무는 시간. 오차를 계산할 좌표계를 고정한다.
Profiling(프로파일링) / Tracy(트레이시)|실행 비용 측정과 시간축 기반 프로파일러. 물리·렌더·센서·디스크 중 어느 단계가 지연되는지 살핀다.
Throughput(스루풋) / VRAM|단위 시간당 처리량과 GPU 전용 메모리. 병렬 환경 수를 늘릴 때 전체 스텝/초와 메모리 최고값을 함께 측정한다.
Telemetry(텔레메트리) / Log(로그)|운영 중 전송하는 상태값과 기록. 목표·실제·시각·단위를 남겨야 실패 위치를 복원할 수 있다.
AMR / Digital Twin(디지털 트윈)|자율 이동 로봇과 가상 대응 모델. 순찰 동선은 가상과 실물에서 같은 목표·지도 정의로 비교한다.
WebRTC / RTSP|실시간 상호작용·미디어 교환 기술과 스트림 제어 프로토콜. 원격 앱 조작 화면과 개별 센서 영상은 목적이 다르다.
Behavior Tree(비헤이비어 트리) / State Machine(스테이트 머신)|행동을 트리로 조합하거나 명시한 상태 사이를 전환하는 방식. 순찰·정지·복귀의 전환 조건을 기록한다.
Emergency Stop(이머전시 스톱) / Watchdog(워치독)|비상 정지 수단과 주기적으로 유효한 명령이 오는지 감시하는 기능. 명령 유효 시간과 복귀 절차는 실물 장비에 맞춘다.

Robot Assembler(로봇 어셈블러) / Surface Gripper(서피스 그리퍼)|로봇 부품을 조립하는 도구와 표면 부착 방식의 집기 기능. 모델 조립과 실행 중 물체 파지를 구분한다.

InteractiveScene(인터랙티브 신) / Environment Spacing(인바이런먼트 스페이싱)|여러 환경의 자산을 구성·갱신하는 장면과 복제본 간 간격. 병렬 환경의 논리 인덱스와 화면 배치를 구별한다.

Pixi(픽시) / Conda(콘다)|환경과 의존성을 관리하는 도구. 예제의 셸 환경을 맞춰야 패키지와 명령이 발견된다.
UR10e / Nova Carter(노바 카터) / Unitree G1(유니트리 지 원)|산업용 로봇팔, 바퀴형 이동 로봇, 휴머노이드 플랫폼 사례. 같은 속도 명령이라도 하위 제어 방식은 기구에 따라 달라진다.
GR00T(그루트) / VLA|NVIDIA의 로봇 기초 모델 계열과 시각·언어·행동을 연결하는 모델. 고수준 작업과 저수준 균형 제어의 입력·출력은 다르다.
ROS Domain ID(로스 도메인 아이디) / DDS|ROS 2 통신 발견 범위에 쓰는 식별자와 대표적인 통신 미들웨어 표준. 토픽이 전혀 보이지 않을 때 환경 설정부터 확인한다.
ONNX Runtime(오닉스 런타임) / TensorRT(텐서알티)|학습된 모델을 실행하는 런타임과 NVIDIA 추론 최적화·실행 도구. 배포 형식, 대상 장치, 지원 연산을 대조한다.
ROS 2 Launch(로스 투 론치) / RViz(알비즈)|여러 노드와 설정을 함께 시작하는 방식과 로봇 데이터 시각화 도구. RViz 화면이 뜨는지와 데이터가 들어오는지는 별도로 확인한다.
Kinematic(키네매틱) / Dynamic(다이내믹)|지정된 운동을 따르는 물체와 힘·접촉으로 운동이 결정되는 물체. 시각 재생과 동역학 시험을 구별하는 단서다.
